# SWIM Operator

Kubernetes Operator for deploying and managing the SWIM DNOTAM stack on OpenShift. Manages the full lifecycle of 4 DNOTAM projects, including databases, messaging, certificates, networking, and observability.

## Managed Custom Resources

| CRD Kind | Project | Infrastructure Provisioned |
|----------|---------|---------------------------|
| `SwimDigitalNotamConsumer` | swim-dnotam-consumer | MongoDB, Kafka (AMQ Streams), mTLS, HPA, ServiceMonitor |
| `SwimDigitalNotamProvider` | swim-dnotam-provider | PostgreSQL, Artemis (AMQ Broker), Kafka, mTLS, OIDC, RBAC, Routes |
| `SwimDnotamConsumerValidator` | swim-dnotam-consumer-validator | MariaDB, Artemis (AMQ), mTLS, Routes, HPA |
| `SwimDnotamProviderValidator` | swim-dnotam-provider-validator | MariaDB, Routes, HPA, mTLS (optional) |

## Prerequisites

### Required Operators (install via OperatorHub before SWIM Operator)

| Operator | Used By | How to Verify |
|----------|---------|---------------|
| **cert-manager Operator for Red Hat OpenShift** | All 4 projects | `oc get pods -n cert-manager` |
| **Red Hat AMQ Broker Operator** | Provider, ConsumerValidator | `oc get csv -n openshift-operators \| grep amq-broker` |
| **Streams for Apache Kafka (AMQ Streams)** | Consumer, Provider (if `kafka.enabled=true`) | `oc get csv -A \| grep amqstreams` |

### Required External Services

| Service | Used By | Notes |
|---------|---------|-------|
| **Keycloak** | Provider (OIDC/JAAS), ProviderValidator | Deploy via RHBK Operator or manually. Requires realm `swim`. |
| **ClusterIssuer `swim-ca-issuer`** | All projects using mTLS | cert-manager ClusterIssuer for certificate issuance. |

#### ClusterIssuer Example

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: swim-ca-issuer
spec:
  ca:
    secretName: swim-ca-secret
```

## Build and Push Images

**IMPORTANT (Mac M1/M2 → OpenShift amd64):** All images are built with `--platform linux/amd64` by default in the Makefile. No extra flags needed.

```bash
cd deploy/swim-operator

make docker-build
make docker-push
```

Default image: `quay.io/masales/swim-openshift-operator:v0.0.1` (configured in Makefile).

## Installation via OLM (OperatorHub)

### One-command OLM refresh

Builds bundle, catalog, pushes both, and reinstalls the CatalogSource on the cluster:

```bash
make olm-refresh
```

This runs: `bundle-build` → `bundle-push` → `catalog-build` → `catalog-push` → remove old CatalogSource → apply new CatalogSource → verify status.

### Install via OpenShift Console

1. Go to **OperatorHub** → search for **SWIM Operator**
2. Click **Install**
3. Select **All namespaces on the cluster** (recommended for multi-namespace CRDs)
4. Update approval: **Manual** or **Automatic**
5. Click **Install**
6. If Manual approval: approve the InstallPlan via console or CLI

### Post-installation verification

```bash
oc get csv -n openshift-operators | grep swim
oc get pod -n openshift-operators | grep swim
oc get crd | grep swim
```

Expected CRDs:
- `swimdigitalnotamconsumers.apps.swim-developer.github.io`
- `swimdigitalnotamproviders.apps.swim-developer.github.io`
- `swimdnotamconsumervalidators.apps.swim-developer.github.io`
- `swimdnotamprovidervalidators.apps.swim-developer.github.io`

## Pre-deploy: SwimDnotamProviderValidator mTLS Certificates

The provider-validator simulates an external ANSP client connecting to the DNOTAM provider via mTLS. Certificates are **not** auto-generated by the operator, the user must provision them manually (simulating a real ANSP receiving EACP certificates).

### Step 1, Create the passwords secret

```bash
oc apply -n <namespace> -f - <<'EOF'
apiVersion: v1
kind: Secret
metadata:
  name: dnotam-provider-validator-passwords
type: Opaque
stringData:
  password: changeit
  PROXY_MTLS_KEYSTORE_PASSWORD: changeit
  PROXY_MTLS_TRUSTSTORE_PASSWORD: changeit
EOF
```

### Step 2, Create the client certificate (cert-manager)

```bash
oc apply -n <namespace> -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: dnotam-provider-validator-client-cert
spec:
  secretName: swim-dnotam-client-tls
  issuerRef:
    name: swim-ca-issuer
    kind: ClusterIssuer
  commonName: dnotam-provider-validator-client
  dnsNames:
    - dnotam-provider-validator-client
    - localhost
  usages:
    - digital signature
    - key encipherment
    - client auth
  privateKey:
    algorithm: RSA
    size: 2048
    rotationPolicy: Always
  keystores:
    pkcs12:
      create: true
      passwordSecretRef:
        name: dnotam-provider-validator-passwords
        key: password
EOF
```

### Step 3, Verify

```bash
oc get certificate dnotam-provider-validator-client-cert -n <namespace>
oc get secret swim-dnotam-client-tls -n <namespace> -o jsonpath='{.data}' | python3 -c "import sys,json; print('\n'.join(sorted(json.load(sys.stdin).keys())))"
```

Expected keys: `ca.crt`, `keystore.p12`, `tls.crt`, `tls.key`, `truststore.p12`

Then reference these secrets in the CR:

```yaml
spec:
  mtls:
    enabled: true
    certsSecretName: "swim-dnotam-client-tls"
    passwordsSecretName: "dnotam-provider-validator-passwords"
```

## Deploying DNOTAM Projects

After the operator is installed, create Custom Resources in your target namespace:

```bash
oc apply -f config/samples/apps_v1alpha1_swimdigitalnotamprovider_minimal.yaml -n <namespace>
oc apply -f config/samples/apps_v1alpha1_swimdigitalnotamconsumer_minimal.yaml -n <namespace>
oc apply -f config/samples/apps_v1alpha1_swimdnotamconsumervalidator_minimal.yaml -n <namespace>
oc apply -f config/samples/apps_v1alpha1_swimdnotamprovidervalidator_minimal.yaml -n <namespace>
```

### Validate deployment

```bash
oc get all -n <namespace>
oc get swimdigitalnotamprovider,swimdigitalnotamconsumer,swimdnotamconsumervalidator,swimdnotamprovidervalidator -n <namespace>
oc get pvc -n <namespace>
oc get routes -n <namespace>
```

## Uninstall

```bash
# Remove CRs
oc delete -f config/samples/ -n <namespace>

# Remove operator subscription and CSV
oc delete sub.operators.coreos.com swim-operator -n openshift-operators
oc delete csv swim-operator.v0.0.1 -n openshift-operators

# Remove CRDs (WARNING: deletes all CRs across all namespaces)
oc delete crd swimdigitalnotamconsumers.apps.swim-developer.github.io
oc delete crd swimdigitalnotamproviders.apps.swim-developer.github.io
oc delete crd swimdnotamconsumervalidators.apps.swim-developer.github.io
oc delete crd swimdnotamprovidervalidators.apps.swim-developer.github.io

# Remove CatalogSource
oc delete catalogsource swim-operator-catalog -n openshift-marketplace
```

### Redeploy operator pod

```bash
oc rollout restart deployment/swim-operator-controller-manager -n openshift-operators
```

## Troubleshooting

### Operator stuck on "Installing" in OpenShift console

The OLM console shows "Installing Operator" indefinitely but never completes.

**Diagnose:**
```bash
oc get sub.operators.coreos.com -n openshift-operators \
  -o custom-columns=NAME:.metadata.name,INSTALLPLAN:.status.installPlanRef.name,INSTALLED:.status.installedCSV

oc logs deployment/catalog-operator -n openshift-operator-lifecycle-manager --tail=100 \
  | grep -i "error\|fail\|swim"
```

**Root cause:** Orphaned subscriptions from other operators in the same namespace block OLM resolution. The catalog-operator loops on the broken subscription and never processes new ones.

**Fix:**
```bash
# Find subscriptions with broken installplan (<none>) and olm.managed=true label
oc get sub.operators.coreos.com -n openshift-operators \
  -o custom-columns=NAME:.metadata.name,INSTALLPLAN:.status.installPlanRef.name,MANAGED:.metadata.labels.olm\\.managed

# Delete the orphaned subscription
oc delete sub.operators.coreos.com <orphaned-subscription-name> -n openshift-operators

# Wait ~30s, then verify the swim InstallPlan was created
oc get installplan -n openshift-operators | grep swim
```

### InstallPlan not approved (Manual approval)

```bash
oc get installplan -n openshift-operators | grep swim
oc patch installplan <installplan-name> -n openshift-operators --type merge -p '{"spec":{"approved":true}}'
```

### Pod with CrashLoopBackOff or ErrImagePull

```bash
oc logs deployment/swim-operator-controller-manager -n openshift-operators
oc describe pod -l control-plane=controller-manager -n openshift-operators
```

Common causes:
- **ErrImagePull:** Image doesn't exist at `quay.io/masales/swim-openshift-operator:v0.0.1`.
- **Exec format error:** Image built for wrong architecture (arm64 instead of amd64). Rebuild with `make docker-build` (includes `--platform linux/amd64`).

### CatalogSource not READY

```bash
oc get pod -n openshift-marketplace | grep swim
oc logs -n openshift-marketplace -l olm.catalogSource=swim-operator-catalog
```

Fix: `make olm-refresh`

### Console shows "A Subscription already exists"

```bash
oc delete sub.operators.coreos.com swim-operator -n openshift-operators
oc delete csv swim-operator.v0.0.1 -n openshift-operators
# Then reinstall via OperatorHub
```
